1. The Assembly Mental Model

In a high-level language, you might write x = a + b. In assembly, you specify exactly where the data comes from, where the operation happens, and where the result goes.

Register

A very fast storage location inside the CPU. It can hold a number, an address, or an intermediate result.

Memory

Where data is stored. Every memory location has an address. You use addresses to read and write data.

A tiny example

MOVS R0, #5
MOVS R1, #3
ADDS R2, R0, R1

Read the lines as follows:

  1. Put the number 5 into R0.
  2. Put the number 3 into R1.
  3. Add R0 and R1, then put the result into R2.
Result: R0 = 5, R1 = 3, R2 = 8.

An assembler translates human-readable instructions into machine code. The CPU ultimately executes that machine code.

2. Syntax and Program Structure

2.1. The shape of an instruction

MNEMONIC{S}  DESTINATION, SOURCE1, SOURCE2

For many three-operand instructions, the destination comes first:

ADD R0, R1, R2    @ R0 = R1 + R2
SUB R3, R4, #2    @ R3 = R4 - 2
  • Mnemonic: the instruction name, such as ADD, MOV, or LDR.
  • Destination: where the result is written.
  • Source: the values the instruction operates on.
  • #: an immediate constant, not a memory address.
  • Label: a named location in the program, usually written with a colon, such as LOOP:.
  • [R1]: the memory location whose address is stored in R1.
  • !: in certain addressing forms, write the updated address back into the base register.
  • {R0,R1,...}: a list of registers used by a multiple-register transfer.
Comment syntax: Your sample uses GNU Assembler directives such as .syntax unified. In GNU AS for ARM, use @ for comments. Your instructor's assembler may use different comment conventions, so follow the environment used in class.

3. ARM Cortex-M3 Registers

The general-purpose ARM registers in this model are 32 bits wide. Each one can hold a 32-bit value.

RegisterAlso calledPurpose
R0–R12General-purpose registersHold data, addresses, and calculation results.
R13SPStack Pointer.
R14LRLink Register; holds the return address for a subroutine call.
R15PCProgram Counter; controls the program's execution location.
xPSR / APSRStatus registersHold processor status and condition flags.
Memorize these: R13 = SP, R14 = LR, R15 = PC. They have special roles and are common targets for conceptual questions.

Example: When BL FUNCTION executes, the return address is stored in LR and execution branches to FUNCTION.

4.5. Immediate operands

The # symbol means that a constant is written directly in the instruction:

MOVS R0, #10
ADD  R1, R0, #5
AND  R2, R1, #0x0F

Hexadecimal numbers use the 0x prefix, for example #0xFF. Not every constant is encodable in every instruction form; if the assembler rejects a value, check that instruction's encoding restrictions.

5. Status Flags, CMP, and the S Suffix

The flags in APSR record information about an operation's result. Conditional branch instructions use these flags to decide whether to branch.

FlagNameSimple meaning
NNegativeThe sign bit of the result is 1.
ZZeroThe result is zero.
CCarryCarry status in addition and related operations.
VOverflowSigned arithmetic overflow.
QSticky saturation flagUsed by relevant saturation instructions.

The very important S rule

ADD  R0, R1, R2    @ Add; normally does not update flags
ADDS R0, R1, R2    @ Add; updates flags

SUB  R0, R1, R2    @ Subtract; does not update flags
SUBS R0, R1, R2    @ Subtract; updates flags
Common exam trap: A register result and the status flags are separate things. A SUB instruction can make R0 equal to zero without changing Z, because it has no S suffix. A later BEQ/BNE may still use flags left by an earlier instruction.

What does CMP do?

CMP R0, R1 behaves like calculating R0 - R1 for the purpose of setting flags. It does not store the subtraction result in a destination register.

CMP R0, #5
BEQ IS_FIVE       @ Branch if equal
BNE NOT_FIVE      @ Branch if not equal

Other comparison/test instructions include CMN, TST, and TEQ. They update flags without writing a normal result to a destination register.

6.3. Standard counter-loop pattern

MOVS R0, #0
LOOP:
    ADDS R0, R0, #1
    CMP  R0, #10
    BNE  LOOP
DONE:
    B DONE

R0 starts at zero. Each iteration adds one, compares R0 with 10, and repeats until R0 equals 10.

6.4. A subroutine

MAIN:
    MOVS R0, #4
    BL DOUBLE
    B FINISH

DOUBLE:
    ADDS R0, R0, R0
    MOV PC, LR

FINISH:
    B FINISH

BL saves the return address in LR. The lecture slides show returning with MOV PC, R14; R14 is the same register as LR.

7. Memory and Load / Store Instructions

ARM uses Load and Store instructions to transfer data between memory and registers. A common pattern is to put an address in a register, then use that register to access memory.

LDR R0, =NUMBERS   @ Put the address of NUMBERS in R0
LDR R1, [R0]       @ Read a 32-bit value from the address in R0
STR R1, [R0]       @ Write R1 to that memory address
Do not confuse these forms:
LDR R0, =NUMBERS means put the address of the label in R0.
LDR R0, [R1] means read a value from the memory address stored in R1.

Load/store mnemonics: full names and meaning

MnemonicExpanded nameData / operation
LDRLoad RegisterRead one 32-bit word from memory into a register.
LDRBLoad Register ByteRead one 8-bit byte and zero-extend it.
LDRHLoad Register HalfwordRead one 16-bit halfword and zero-extend it.
LDRSBLoad Register Signed ByteRead one signed byte and sign-extend it to 32 bits.
LDRSHLoad Register Signed HalfwordRead one signed 16-bit halfword and sign-extend it to 32 bits.
STRStore RegisterWrite one 32-bit word from a register to memory.
STRBStore Register ByteWrite the low 8 bits of a register to memory.
STRHStore Register HalfwordWrite the low 16 bits of a register to memory.

Name pattern: B means byte, H means halfword, and S in LDRSB/LDRSH means signed. Here, LDRSH literally expands to Load Register Signed Halfword.

When moving through consecutive array elements, the address increment depends on the element size:

  • Byte array: advance by 1 byte.
  • Halfword array: advance by 2 bytes.
  • Word array: advance by 4 bytes.

Little-Endian byte order

In Little-Endian format, the least significant byte (LSB) is stored at the lowest address. For example:

bytes: .byte 0x12, 0x34, 0x56, 0x78

LDR R0, =bytes
LDRH R1, [R0]       @ R1 = 0x3412
LDRH R2, [R0, #2]   @ R2 = 0x7856
If the first two bytes are 0x12 and 0x34, the halfword value in Little-Endian order is 0x3412, not 0x1234.

9. Multiple Transfers, LDM/STM, and the Stack

9.1. LDM and STM

  • LDM = Load Multiple; loads several memory values into several registers.
  • STM = Store Multiple; stores several registers into memory.
  • IA = Increment After; addresses increase, and the first transfer uses the base address.
  • IB = Increment Before; the address is incremented before the first transfer.
  • DA = Decrement After; transfers use decreasing addresses, after the base.
  • DB = Decrement Before; the address is decremented before the first transfer.
LDR   R0, =NUMBERS
LDMIA R0!, {R1, R2, R3, R4}

If R0 initially contains address 0x1000, the values are loaded like this:

Destination registerMemory address
R10x1000
R20x1004
R30x1008
R40x100C
Key rule from the lecture: The lowest-numbered register gets the lowest memory address. The order in which register names are typed inside the braces does not change the transfer order. With !, the base register is also updated.

9.2. The stack

In the Full Descending stack model, the stack grows toward lower memory addresses. The lecture shows the standard pattern with these instructions:

STMFD SP!, {R0, R1, R2}   @ Push
LDMFD SP!, {R0, R1, R2}   @ Pop

STMFD is equivalent to STMDB, and LDMFD is equivalent to LDMIA for the standard Full Descending stack convention.

10. Walk Through Your Three-Page Assembly Example

This example combines several topics: data definitions, loading multiple words, byte and halfword loads, addition, storing results, and a BEQ condition.

10.1. Read the data definitions first

numbers:   .word 10, 20, 30, 40
bytes:     .byte 0x12, 0x34, 0x56, 0x78
halfwords: .hword 0x1234, 0x0000

sum_result:  .word 0
byte_result: .byte 0
half_result: .hword 0

10.2. Load four numbers and add them

LDR R0, =numbers
LDMIA R0!, {R1, R2, R3, R4}

ADD R5, R1, R2
ADD R5, R5, R3
ADD R5, R5, R4
  1. R1=10, R2=20, R3=30, R4=40.
  2. R5 = 10 + 20 + 30 + 40 = 100.
  3. Four words were loaded, so R0 advances by 4 × 4 = 16 bytes.

10.3. Load two bytes, add them, and store the result

LDR R6, =bytes
LDRB R7, [R6], #1
LDRB R8, [R6], #1
ADD R7, R7, R8
STRB R7, [R6]
  1. R7 = 0x12, then R6 advances by one byte.
  2. R8 = 0x34, then R6 advances by another byte.
  3. R7 = 0x12 + 0x34 = 0x46.
  4. The value 0x46 is stored in the third byte of the array.

10.4. Load and add halfwords

LDRH R9, [R6]
LDR R10, =halfwords
LDRH R11, [R10]
ADD R11, R11, R9
STRH R11, [R10, #2]
  • After the two post-indexed loads, R6 points to the third byte of the byte array.
  • The two bytes there are 0x46 and 0x78. In Little-Endian order, R9 = 0x7846.
  • R11 initially contains 0x1234.
  • R11 = 0x1234 + 0x7846 = 0x8A7A.
  • The value 0x8A7A is stored in the second halfword of halfwords.

10.5. The final condition

CMP R5, #100
BEQ EQUAL
MOVS R0, #0
B FINISH

EQUAL:
MOVS R0, #1

FINISH:
B FINISH

Because R5 equals 100, CMP sets Z=1. Therefore BEQ is taken, and R0 becomes 1. The program then stays in the FINISH loop.

Important final values: R5 = 100, R7 = 0x46, R9 = 0x7846, R11 = 0x8A7A, and R0 = 1 on the final path.

11. Common Exam Traps

  1. MOV is not LDR: MOV copies a register/immediate value; LDR reads memory or, with the equals form, loads a label address.
  2. LDR and STR have opposite directions: LDR transfers memory to a register; STR transfers a register to memory.
  3. Data size matters: LDRB reads one byte, LDRH reads two bytes, and LDR reads one word.
  4. Post-index: access memory first, then update the base register.
  5. Pre-index with !: update the base register as part of the access.
  6. ! with LDM/STM: updates the base register after the multiple transfer.
  7. LDM/STM register order: register number determines the address order, not the order in which names appear in braces.
  8. SUB versus SUBS: SUB does not update flags; SUBS does.
  9. CMP: does not store a subtraction result in a general-purpose register; it updates flags.
  10. BNE: branches when Z=0. It does not directly inspect a register's numeric value.
  11. Label spelling: keep the capitalization of a label identical everywhere.
  12. Little-Endian: the least significant byte is stored at the lowest address.
  13. Signed versus unsigned: GT and HI are not interchangeable. GT is signed; HI is unsigned.
