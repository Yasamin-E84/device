CHAPTER 1

Embedded Systems — the basics

1. What is an embedded system?

Definition: An embedded system is an information-processing system built into a larger product. It is a combination of hardware and software that performs a specific function as part of a larger device.

Its main purpose is usually not general information processing like a desktop computer. The user buys the larger device for what it does, not because it contains a computer.

Examples: a digital camera, washing machine controller, car braking controller, printer, microwave, medical device, or smart thermostat.

Remember: It is a computer hidden inside another product. It senses something, makes a decision, and controls an action.

Understand the digital-camera diagram

A digital camera is an embedded system.

  1. Lens: lets light enter the camera.
  2. CCD sensor: converts incoming light into an electrical signal.
  3. A/D converter: converts the analog sensor signal into digital data that the processor can work with.
  4. Processor / CPU: controls the camera and processes data.
  5. Memory: stores the program and/or image data. The slide shows Flash, DRAM, and a memory card.
  6. Co-processors: specialized units such as a camera DSP or JPEG co-processor help with specific processing tasks.
  7. I/O control and interfaces: connect the camera to devices such as an LED, LCD, USB/serial interface, Bluetooth, or Ethernet.
  8. Software: tells the hardware what operations to perform.
Light → CCD → A/D conversion → processor + memory → image / display / communication

Hardware

  • Analog/digital converters
  • Application-specific integrated circuits (ASICs)

Software

  • Application program
  • Program logic
  • Instructions executed by the processor
  • Code that reads inputs and controls outputs

2. GP processor, SP processor, ASIC, and NRE

GP means General-Purpose. A general-purpose processor is flexible: it can run many different programs and perform many kinds of tasks.

SP means Single-Purpose. A single-purpose processor is designed for one particular task. An ASICمدار مجتمع با کاربرد خاص
A chip designed for a particular application rather than many unrelated tasks. is an example of custom hardware for a specific function.

General-purpose (GP)

  • Programmable controller
  • Control logic is stored in memory
  • Has fetch/decode overhead
  • General datapath and many registers
  • Flexible; can run different programs

ASIC / single-purpose

  • Hardwired controller
  • Does not need program memory for that fixed function
  • No normal fetch/decode overhead for the hardwired logic
  • Datapath is tuned for its task
  • Fast and efficient for its specific job, but less flexible

What does NRE mean?

NRE (Non-Recurring Engineering)هزینه مهندسی غیرتکرارشونده
A one-time engineering/design cost, rather than a cost repeated for every manufactured unit. is the one-time cost of designing and developing something, such as a custom chip.

Example: designing a custom chip takes a large amount of engineering work once. After the design is finished, manufacturing additional copies does not require repeating the original design work.

The lecture slide compares GP and ASIC using “NRE / sale-volume”. For the exam, recognize the term and understand that the one-time design cost is considered in relation to how many units will be sold. The slide labels GP as high and ASIC as low for this comparison.

What to be able to say: NRE is a non-recurring, one-time engineering cost. It matters when deciding whether a custom single-purpose design is worthwhile for the expected sales volume.

How do ASIP and ASIC differ?

An ASIP is a programmable processor optimized for a specific class of applications. It has a specialized instruction set and datapath, but it still executes instructions. An ASIC is a custom integrated circuit designed for a specific function and generally uses hardwired logic. ASIP is more flexible, while ASIC can be more efficient for a fixed task.

3. Memory and Write-ability — optional until confirmed

Memory stores bits (0s and 1s). One feature is Write-abilityقابلیت نوشتن / امکان برنامه‌ریزی حافظه
How easily and how quickly the processor or another device can write new data into memory.: how easily and quickly new data can be written.

  • High write-ability: the processor can write quickly and easily. Example: RAM.
  • Middle: the processor can write, but more slowly. Examples: Flash and EEPROM.
  • Low: special equipment (a programmer) is needed. Examples: EPROM and OTP ROM.
  • Very low: data is fixed during manufacturing. Example: mask-programmed ROM.

Do not confuse: Write-ability is about how easily memory can be written. Storage permanence is about whether it keeps data after power is removed.

4. Communication: serial, parallel, IR, and RF

Serial communication

Serial communicationارتباط سریال
Data is sent one bit after another over a data line, rather than using many data wires at once. transfers data one bit after another. The lecture describes one data wire plus one or more control wires (although some protocols do not need extra control wires).

  • Uses fewer wires, so cable cost can be lower.
  • Useful for communication over longer distances or between processing nodes.
  • Examples from the slide: USB, Ethernet, RS-232, and I²C.

Parallel communication

Parallel communicationارتباط موازی
Several data wires carry multiple bits at the same time. uses multiple data wires at the same time.

  • Can provide higher throughput over short distances.
  • Needs more wires, so cable cost is higher.
  • Can have a data-misalignment problem.
  • Examples from the slide: ISA, AMBA, and PCI.

UART — know the basic idea

UARTفرستنده/گیرنده سریال ناهمگام
A hardware unit that converts parallel data to serial when sending, and serial data back to parallel when receiving. means Universal Asynchronous Receiver/Transmitter.

  • Sending: takes parallel data and transmits it serially.
  • Receiving: takes serial data and converts it to parallel.
  • Start bit marks the beginning of a frame.
  • Stop bit marks the end of a frame.
  • Parity bit is an extra bit used for simple error checking.
  • Baud rate is the number of signal changes/symbols per second. It is not always identical to bit rate.

Infrared (IR) — skim-level

  • Uses electromagnetic waves just below the visible-light spectrum.
  • A diode emits infrared light; a detector receives it.
  • Cheap to build.
  • Needs line of sight and has limited range.

Radio Frequency (RF) — skim-level

  • Uses electromagnetic waves in the radio spectrum.
  • Needs suitable analog circuitry and an antenna on both sides.
  • Does not require line of sight.
  • Transmitter power affects the communication range.

Easy difference: IR generally needs a clear path; RF can work without direct line of sight.

5. Characteristics of embedded systems

Characteristics vary by system.

  1. Dependability: the system should be trustworthy. It includes:
    • Reliabilityقابلیت اطمینان
      It continues to work correctly over time.
    • Maintainabilityتعمیرپذیری / نگهداشت‌پذیری
      It can be repaired or maintained without excessive difficulty.
    • Availabilityدر دسترس بودن
      It is ready to provide its service when needed.
    • Safetyایمنی
      It should not cause unacceptable harm.
    • Securityامنیت
      It should resist unauthorized access or misuse.
  2. Energy efficiency: it should use power carefully.
  3. Performance: it must be fast enough for its assigned task.
  4. Real-time constraints: the answer must arrive before the required deadline. A correct answer that arrives too late may count as a wrong answer.
  5. Weight, cost, and code-size efficiency: the design should avoid unnecessary size, weight, cost, and program memory.
  6. Dedicated application: it is designed toward a particular job; the goal is to minimize resources and maximize robustness.
  7. Dedicated user interface: it may not need a normal mouse, keyboard, and screen.
  8. Connection to the physical world: it often uses sensors and actuators.
  9. Hybrid design: it may contain both analog and digital parts.
Quick recall — characteristics: dedicated purpose · real-time deadlines · reliability / dependability · energy efficiency · performance · low cost / size / weight · sensor and actuator interaction · limited resources · possible analog + digital hardware.
Important: not every embedded system has every characteristic.
Exam check: name five characteristics of an embedded system.
Dedicated application, real-time constraints, dependability, energy efficiency, and interaction with the physical world through sensors and actuators. Other points include performance, cost, size, weight, code-size efficiency, and a dedicated user interface.

Sensor vs. actuator

Sensor = input

Measures something in the environment and sends information to the system. Example: temperature sensor, light sensor, or button.

Actuator = output

Does something in the environment when the system commands it. Example: motor, valve, buzzer, or LED.

6. Real-time, hard real-time, and soft real-time

A real-time systemسیستم بلادرنگ
A system whose response must arrive within a specified time limit. must produce its response within a specified timing constraint. The system has a deadlineمهلت زمانی
The latest time by which a task must finish..

Hard real-time

Missing the deadline may have disastrous or unacceptable consequences. The deadline is critical.

Example: an airbag controller must react at the required moment. A late response is not useful.

Soft real-time

Missing a deadline occasionally is not disastrous. Some delay may be tolerated with an acceptably low probability.

Example: a video stream may briefly drop a frame or become less smooth; the whole system does not become dangerous.

Exam-ready comparison: In hard real-time systems, missing the deadline can cause disastrous consequences. In soft real-time systems, occasional deadline misses are tolerable and do not cause disastrous consequences.

7. What is a processor?

A processorپردازنده
The computing engine that executes instructions and processes data. executes a program. In the lecture, instructions are normally executed one after another. The processor repeatedly performs a fetch/execute cycleچرخه واکشی و اجرا
The processor fetches an instruction, then executes it.:

  1. Fetch the next instruction from memory.
  2. Execute that instruction.
  3. Move to the next instruction, unless a branch or another operation changes the flow.

The flow of the program is controlled by changes to the Program Counter (PC).

Three instruction classes

  • Data instructions: move data and perform arithmetic or logical operations.
  • Control instructions: branch, loop, or call a subroutine.
  • Interface / data-transfer instructions: load from or store to external memory.

General-purpose processor vs. embedded processor

General-purpose processor

  • Programmed by the user.
  • Must handle many different applications.
  • Often uses memory as the main way to communicate with devices.
  • Can use high-level languages, compilers, debuggers, and flexible data structures.
  • Usually more expensive/larger than a simple embedded processor.
  • Does not automatically care how much time has passed; it runs the work it is given.

Embedded processor / microcontroller

  • Often programmed once for the product by its manufacturer.
  • Runs one program or a limited set of programs.
  • Task-specific and optimized for its application.
  • Directly senses and controls signal wires.
  • Communicates with devices using protocols.
  • Often has real-time interactions and timing constraints.

Why do processors need performance improvements?

Traditional processor architecture tries to improve performance. The lecture lists three techniques:

  1. Cache: a small, fast memory close to the processor. It keeps frequently used data/instructions nearby, reducing the time spent waiting for slower main memory.
  2. Branch prediction: the processor predicts which direction a conditional branch will take, so it can prepare the likely next instructions instead of waiting.
  3. Multiple / out-of-order issue: the processor can issue more than one instruction in a cycle and/or execute independent instructions when their data is ready, rather than waiting rigidly for the original order.

8. What is a microcontroller, and why do we use one?

Definition: A microcontroller (MCU)میکروکنترلر
A small computer built into a single integrated circuit (chip). is a small computer on a single integrated circuit. It contains one or more CPU cores, memory, and programmable input/output peripherals. It is designed mainly for embedded applications.

Typical parts on one chip:

  • CPU / processor core
  • RAM
  • ROM / Flash
  • Input/output ports
  • Timers and counters
  • Communication interfaces
  • Sometimes ADC / DAC and other peripherals

Microprocessor vs. microcontroller

Microprocessor

The CPU is the main chip. It normally needs separate supporting chips for memory and I/O.

CPU + external memory + external I/O

Microcontroller

CPU, memory, and many supporting peripherals are integrated into one chip.

CPU + memory + I/O on one chip

Why move toward microcontrollers? Embedded products need to read input wires, control output wires, communicate with peripherals, and measure time. A microcontroller integrates the processor and the common support hardware, making the system smaller and more suitable for a dedicated task.

Why can't the processor do everything by itself?

An embedded program may need to:

  • Read input bits from sensors or buttons.
  • Change output bits to control devices.
  • Perform calculations.
  • Measure time and keep events precisely spaced.
  • Communicate using standard protocols.

If the CPU tries to measure every tiny timing detail by repeatedly checking a loop, it stays busy and may still be inaccurate. Dedicated hardware peripherals, timers, and communication units can do standard jobs in parallel and reduce the CPU's workload.

9. Memory-mapped I/O

Memory-mapped I/Oورودی/خروجی نگاشت‌شده در حافظه
Some addresses in the processor's address space refer to peripheral registers instead of ordinary RAM. means that some addresses in the processor's address space are assigned to I/O devices.

In simple words: the processor communicates with a device by reading from or writing to a particular address, just as it reads or writes memory.

  • Writing 1 to a GPIO output address may turn a pin/LED on.
  • Writing 0 may turn it off.
  • Reading a button's mapped address may return 1 when pressed and 0 when not pressed.

Bus words you should recognize

  • Initiator: the device that starts a transaction (often the processor).
  • Target: the device that responds to the request (often a peripheral).
  • Bus master: a device that can initiate a transaction.
  • Slave: a device that can only respond as a target.

In the example bus from the lecture:

  • CMD = 0 means read; CMD = 1 means write.
  • REQ# low means the initiator is requesting a transaction.
  • ACK# low means the target has completed its part.

Read transaction: the initiator places an address and read command on the bus, requests the transaction, the target places the data on the bus and acknowledges, then the initiator reads the data and the transaction ends.

Write transaction: the initiator places the address, write command, and data on the bus, requests the transaction, the target reads/stores the data and acknowledges, then the transaction ends.

10. Timers, Input Capture, and Output Compare

A timerزمان‌سنج
A hardware counter that counts clock events to measure time or schedule an event. is a hardware unit that counts clock pulses. It can measure a time interval or cause something to happen at a chosen time.

Why use a hardware timer? It can count independently while the processor does other work. The processor can set it, read it, and respond when it expires.

  • Measure how long something takes.
  • Make something happen once or repeatedly after a time interval.
  • A timer may generate an interrupt when it reaches its limit.
  • A self-reloading timer can restart automatically for regular events.
  • A prescaler can divide the incoming clock to measure longer intervals.
  • A timer may also be started by an external event.

Input Capture = record when an input event happened

Input Captureثبت زمان رویداد ورودی
The timer saves its current count immediately when a selected input event occurs. records the timer value at the exact moment an input event occurs.

Example: measuring fan speed. Each fan rotation creates a pulse. The timer records the time of each pulse. The difference between two recorded times tells us how long one rotation took, which helps calculate the speed.

Why is this better than waiting for the CPU to notice the pulse? The hardware captures the time immediately, even if the CPU is busy.

Output Compare = make an output event happen at a chosen time

Output Compareمقایسه خروجی
The timer compares its count with a preset value and triggers an output action when they match. sets an output event to happen when the timer reaches a predefined value.

Example: configure the timer to change an output pin after 1,000 clock ticks. The processor can do other work while the timer counts.

Capture vs. Compare

Capture

“When did the input event happen?”

It records the current timer value.

Compare

“When should the output event happen?”

It triggers an action when the count reaches a preset value.

Watchdog Timer — understand the sequence

A Watchdog Timer (WDT) is a safety timer that checks whether the software is still running correctly. The program must periodically refresh, restart, or “kick” the watchdog before its countdown expires.

1 · StartWatchdog begins counting
→
2 · RefreshHealthy program resets the timer
→
3 · Timeout?No refresh before the limit
→
4 · RecoveryInterrupt or system reset
  • Normal operation: the program refreshes the watchdog regularly, so it does not expire.
  • Program hangs: the program stops refreshing it; the watchdog reaches its timeout.
  • Result: the watchdog can generate an interrupt or reset the microcontroller, depending on its configuration.
  • Purpose: recover from software faults such as an infinite loop or a system that becomes unresponsive.
Exam-ready answer: A Watchdog Timer monitors the execution of an embedded system. Software must periodically refresh it. If the program fails to do so before the timeout, the watchdog generates a recovery action, commonly resetting the system.
Exam check: what happens if the CPU gets stuck in an infinite loop?
If the infinite loop prevents the program from refreshing the watchdog, the watchdog times out and can reset the microcontroller or trigger its configured recovery interrupt.
Exam check: is the watchdog the same as an ordinary timer?
Both count time, but their purposes differ. An ordinary timer is commonly used to measure intervals or schedule events. A watchdog checks that software continues to refresh it and can recover the system if it does not.
Picture question: what does the timer do while the CPU is busy?
The hardware timer continues counting independently. It can capture an event or trigger an interrupt / output action without the CPU counting every clock pulse in software.
Picture question: what does Top mean?
Top is the timer's configured maximum / terminal count value. Reaching it can cause a timer event, depending on the timer configuration.

Word size and endianness

The ARM Cortex-M3 is a 32-bit processor architecture. Its general registers are 32 bits wide.

The order in which the bytes of a multi-byte value are stored in memory. tells us which byte of a multi-byte value is stored at the lower memory address.

  • Little-endian: the least significant byte is stored at the lowest address.
  • Big-endian: the most significant byte is stored at the lowest address.

What is the Program Counter (PC) for?

The PC is R15. It keeps track of where the processor should fetch the next instruction from.

  • Normally, the program proceeds sequentially from one instruction to the next.
  • A branch instruction changes the PC to a different address.
  • That is how loops, decisions, jumps, and subroutine calls change the execution flow.
Short exam answer: The Program Counter stores the address of the next instruction in the program flow. Branch instructions modify it to change which instruction executes next.

Thumb-2 note

The Cortex-M3 uses the Thumb instruction set with Thumb-2 extensions. Instructions can be 16 or 32 bits long.

In the ARM syntax shown in the lecture, the destination register is written first. For example, ADD R0, R1, R2 means “put the sum of R1 and R2 into R0”.

Worked register example

Suppose the question gives:

R1 = 0x2C and R2 = 0x14

Convert to 8-bit binary so you can see the bits:

R1 = 0x2C = 0010 1100
R2 = 0x14 = 0001 0100
  • ADD: 0x2C + 0x14 = 0x40 = 0100 0000.
  • SUB: 0x2C − 0x14 = 0x18 = 0001 1000.
  • EOR / XOR: 0010 1100 XOR 0001 0100 = 0011 1000 = 0x38.

Which bits are 1 in 0x38? Write the bit positions above the binary digits. Bit 0 is the rightmost bit:

Bit:   7 6 5 4 3 2 1 0
Value: 0 0 1 1 1 0 0 0

Therefore, the set bits are bit 5, bit 4, and bit 3.

How to identify a bit

  • Bit numbering starts at 0 from the right.
  • The rightmost bit is bit 0 (least significant bit / LSB).
  • The leftmost bit in a 32-bit register is bit 31 (most significant bit / MSB).
  • To test bit n, compare the value with a mask that has only bit n set. In a calculation, you can use 1 << n to create that mask.
  • To set a bit, use OR with a mask. To clear a bit, use BIC or AND with the inverted mask. To test a bit, use AND or TST.

14. Status flags, comparisons, and branches

The status register contains condition flags. They help the processor make decisions after an operation.

FlagNameMeaning
NNegative1 when the result is negative (the top/sign bit is 1).
ZZero1 when the result is zero.
CCarryIndicates a carry condition in unsigned arithmetic.
VOverflowIndicates signed arithmetic overflow.

Very important: ADD vs. ADDS, SUB vs. SUBS

  • ADD performs addition but does not update the condition flags in the basic form.
  • ADDS performs addition and updates the flags.
  • SUB performs subtraction but does not update the flags in the basic form.
  • SUBS performs subtraction and updates the flags.
  • CMP R1, R2 compares the values by internally calculating R1 − R2 and updating the flags. It does not save the subtraction result in a destination register.
Exam trap: a subtraction can produce zero, but if the instruction is SUB (without S), the Z flag may remain unchanged. Do not assume every arithmetic instruction updates flags.

Common branch instructions

  • B LABEL: branch unconditionally to LABEL.
  • BEQ LABEL: branch if equal, meaning Z = 1.
  • BNE LABEL: branch if not equal, meaning Z = 0.
  • BL LABEL: branch with link; saves the return address in LR and branches to a subroutine.

Subroutine: a smaller section of a program that performs a task and can be called from another part of the program. LR helps the processor return after the subroutine.

Trace the lecture's short branch example

MOVS R0, #1
MOVS R1, #1
MOVS R2, #1
SUB  R0, R1
BNE  done
MOVS R2, #2
done:
B done
  1. Each MOVS stores 1 and updates the flags. Since the value is 1, Z becomes 0.
  2. SUB R0, R1 calculates R0 = 1 − 1 = 0.
  3. But the instruction is SUB, not SUBS. Therefore, it does not update Z. Z stays 0 from the earlier MOVS.
  4. BNE means branch if Z = 0. The branch is taken.
  5. The instruction MOVS R2, #2 is skipped.
  6. R2 remains 1.

Final answer: R2 = 1. The point of the question is to notice the difference between SUB and SUBS.

15. Load, store, and addressing modes

Processors use load and store instructions to move data between memory and registers.

  • LDR: load a word from memory into a register.
  • STR: store a word from a register into memory.
  • LDRB / STRB: load/store one byte.
  • LDRH / STRH: load/store one halfword (16 bits).
  • LDRSH: load a signed halfword and extend its sign.

Examples:

LDR R0, [R1]       ; read a word from memory at address in R1
STR R0, [R1]       ; write R0 to memory at address in R1
LDRB R0, [R1]      ; read one byte
LDRH R0, [R1]      ; read one halfword

Important difference: LDR R0, =LABEL is a common assembler pseudo-instruction that places the address of LABEL into R0. LDR R0, [R1] reads the data stored at the address in R1.

Three addressing forms

FormExampleWhat happens?
OffsetLDR R0, [R1, #4]Use address R1 + 4. R1 itself does not change.
Pre-indexedLDR R0, [R1, #4]!Add 4 to R1 first, use the new address, and write the new address back to R1.
Post-indexedLDR R0, [R1], #4Use the old address in R1 first, then add 4 to R1.

The exclamation mark ! means write the updated address back into the base register.

16. Multiple-register transfer — ES2 PDF p.65

LDMبارگذاری چند رجیستر
Load Multiple: load several registers from consecutive memory locations. loads multiple registers from memory. STMذخیره چند رجیستر
Store Multiple: store several registers into consecutive memory locations. stores multiple registers into memory.

The register list is written inside braces, for example {R0, R1, R5}. The lowest-numbered register is associated with the lowest memory address, then the next register with the next word address.

LDMIA R0!, {R1, R2, R3, R4}

Read this as:

  1. R0 contains the starting memory address.
  2. Load the first word into R1.
  3. Load the next word into R2.
  4. Continue into R3 and R4.
  5. Because of !, update R0 after the transfer.

Understand the four address modes on page 65

  • IA — Increment After: addresses increase; the first transfer uses the base address.
  • IB — Increment Before: addresses increase; the base is incremented before the first transfer.
  • DA — Decrement After: addresses decrease; the base is used before the decrement sequence.
  • DB — Decrement Before: addresses decrease; the decrement happens before the first transfer.

Memory trick: I = Increment, D = Decrement, A = After, B = Before.

With the ! suffix, the updated base address is written back to the base register.

What to practise: given a starting address and a register list, identify which register receives data from the first address, which receives the next word, and how the base register changes. Practise reading and sketching the address movements; a small label or address in the diagram may be the question.

17. Tracing an assembly program

This program processes arrays of words, bytes, and halfwords.

First: understand the data declarations

  • .word defines 32-bit values (4 bytes each).
  • .byte defines 8-bit values (1 byte each).
  • .hword defines 16-bit values (2 bytes each).
  • .text marks the program/code section.
  • .data marks the data section.

The worksheet begins with:

Numbers:    .word 10, 20, 30, 40
Bytes:      .byte 0x12, 0x34, 0x56, 0x78
Halfwords:  .hword 0x1234, 0x0000

Part A — load four numbers and add them

LDR   R0, =Numbers
LDMIA R0!, {R1, R2, R3, R4}

ADD R5, R1, R2
ADD R5, R5, R3
ADD R5, R5, R4

Meaning:

  • R0 receives the address of the Numbers array.
  • LDMIA loads 10, 20, 30, and 40 into R1, R2, R3, and R4.
  • The ADD instructions add them step by step.

Result: R5 = 10 + 20 + 30 + 40 = 100.

Part B — read bytes, add two, and store the result

LDR  R6, =Bytes
LDRB R7, [R6], #1
LDRB R8, [R6], #1
ADD  R7, R7, R8
STRB R7, [R6]

Meaning:

  • R6 points to the first byte.
  • The first LDRB reads 0x12 into R7, then increases R6 by 1.
  • The second LDRB reads 0x34 into R8, then increases R6 by 1 again.
  • ADD makes R7 = 0x12 + 0x34 = 0x46.
  • STRB stores the one-byte result 0x46 at the current address, which is the third byte's position.

So the byte array becomes 12 34 46 78.

Part C — read halfwords and add them

LDRH R9, [R6]
LDR  R10, =Halfwords
LDRH R11, [R10]
ADD  R11, R11, R9
STRH R11, [R10, #2]

Meaning:

  • R6 now points to the third byte. LDRH reads two bytes from there.
  • Assuming the little-endian byte order used for this example, bytes 0x46 0x78 form the halfword 0x7846.
  • R10 receives the address of the Halfwords array.
  • LDRH reads the first halfword 0x1234 into R11.
  • ADD gives 0x1234 + 0x7846 = 0x8A7A.
  • STRH stores the result at offset 2, which is the second halfword's location.

Result: the second halfword becomes 0x8A7A.

Part D — save results and make a decision

STR  R5,  [address of Sum_result]
STRB R7,  [address of Byte_result]
STRH R11, [address of Half_result]

CMP R5, #100
BEQ EQUAL
  • STR saves the 32-bit sum (100).
  • STRB saves the byte result (0x46).
  • STRH saves the halfword result (0x8A7A).
  • CMP compares R5 with 100 and sets the condition flags.
  • Because R5 is 100, the comparison result is zero and Z = 1.
  • BEQ means “branch if equal”, so the program jumps to EQUAL.
  • The equal path sets R0 to 1. If the values were not equal, the other path would set R0 to 0.
Final values to understand: R5 = 100, R7 = 0x46, R11 = 0x8A7A. The comparison is equal, so the equal branch is taken and R0 becomes 1.

Memory Mapping · two related ideas you must not confuse

1. Memory map / address map

A memory map shows how the processor's address space is divided into regions, such as code, SRAM, peripherals, and external devices.

It answers: “What kind of memory or device is located at this address?”

Peripheral control and data registers are assigned addresses in the processor's address space. The CPU reads or writes those addresses to communicate with devices.

Memory Mapping · short exam answer

A memory map describes how a processor's address space is assigned to different regions, such as program code, RAM, peripherals, and external devices. In memory-mapped I/O, peripheral registers are given addresses in that same address space, so the processor can access them using normal memory read and write operations.

Do not mix these two terms

Memory map: the overall address-space layout. Memory-mapped I/O: the method of accessing peripheral registers through assigned addresses. MMIO is one use of the processor's address map.

Microcontroller and processor design questions

Draw and label a microcontroller.

A microcontroller is a small computer integrated into one chip. Its main blocks include a CPU core, program memory (Flash / ROM), data memory (RAM), an internal bus, and peripherals such as GPIO, timers, and communication interfaces. Depending on the device, it may also include an ADC, PWM, or other special-purpose units. The CPU reads inputs, processes data, and controls outputs.

Drawing order: draw the chip boundary → place the CPU in the centre → add Flash / ROM and RAM → add the bus → add I/O and peripheral blocks → show input and output connections.

Compare ASIP and ASIC.

An ASIP is a programmable processor designed for a particular class of applications. It still has an instruction set and executes instructions, but its datapath and operations are optimized for that application area. An ASIC is custom hardware designed for a specific function. It usually uses hardwired control rather than a general program stored in program memory. Therefore, an ASIP keeps more flexibility, while an ASIC can be more efficient for its fixed task.

Infrared (IR)مادون قرمز — communication using infrared light.
Radio Frequency (RF)فرکانس رادیویی — communication using radio waves.
Sensorحسگر — reads/measures something.
Actuatorعملگر — causes a physical action.
Real-timeبلادرنگ — must respond within a time limit.
Deadlineمهلت زمانی — latest acceptable completion time.
Timerزمان‌سنج — counts clock events to measure/schedule time.
Input Captureثبت زمان ورودی — records when an input event happens.
Output Compareمقایسه خروجی — triggers an output at a preset timer count.
Program Counter (PC)شمارنده برنامه — tracks the next instruction address.
Link Register (LR)ثبات پیوند — stores a subroutine return address.
Stack Pointer (SP)اشاره‌گر پشته — points to the stack location.
Flagپرچم وضعیت — a status bit such as zero or negative.
Immediateمقدار ثابت در دستور — a value written directly in an instruction.
Operandعملوند — a value used by an instruction.
XOR / EORیا انحصاری — output is 1 when input bits differ.
LSLشیفت منطقی به چپ — shifts bits left and fills with zeros.
LSRشیفت منطقی به راست — shifts bits right and fills with zeros.
ASRشیفت حسابی به راست — shifts right while copying the sign bit.
RORچرخش به راست — bits leaving the right side re-enter on the left.
RRXچرخش توسعه‌یافته به راست — rotates one bit through the carry flag.
LDR / STRبارگذاری / ذخیره — move data between memory and registers.
LDM / STMبارگذاری / ذخیره چندگانه — transfer several registers at once.
Addressing modeشیوه آدرس‌دهی — how an instruction calculates the memory address.
Offsetافست / جابه‌جایی — a value added to or subtracted from a base address.
Write-backبازنویسی آدرس — saves an updated address into the base register.
